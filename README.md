# 规划法规RAG

一个面向城市规划法规场景的智能检索与问答系统。项目服务于城市规划管理、责任规划师和基层执法辅助场景，以规划法规、管理技术规定、专项规范等资料为知识源，将分散的政策文本整理为可检索、可追溯、可评测的法规知识库，帮助使用者快速定位适用条款、核验原文依据，并降低人工翻阅规范的成本。

公开仓库中的 `data/source` 为脱敏演示材料，不包含真实项目资料或个人 API Key。

## 项目背景

在密云区责任规划师相关工作中，基层业务人员经常遇到三类问题：

- 法规资料分散，涉及上位规范、区级控规、专项设施标准和通知类政策，人工查找成本高。
- 业务问题往往是口语化表达，例如“养老设施怎么配”“退线多少米”，但法规原文使用的是正式条款语言。
- 规划法规存在地区、版本、效力状态差异，回答必须保留来源、条款和适用边界，不能只给泛化结论。

因此，本项目将目标定义为：不是做一个泛聊天机器人，而是做一个面向法规检索的“证据优先型”AI 产品。

## 核心能力

- 条款级分块：优先按法规标题、章节、条款进行切分，保留条款号、文号、地区、效力状态等元数据。
- 混合检索：同时使用向量检索、BM25/全文检索和关键词规则，提高口语化问题与正式法规文本之间的匹配率。
- 业务重排：根据条款号、法规名称、地区层级、内容类型和现行有效状态进行排序优化。
- 可追溯回答：每条回答都返回引用来源，展示命中的法规名称、章节条款和原文片段。
- 质量评测：使用冻结测试集评估 Recall@5、MRR、Top-1 条款准确率和 nDCG@5，用数据驱动迭代。
- 增量更新：通过文档哈希判断内容是否变化，只对新增或变更文档重新入库。

## 效果指标

项目基于 100 道分层法规检索测试集进行评测，覆盖条款定位、设施配置、许可材料、日照与退线等典型问题。在不更换测试集的前提下，通过优化分块策略、条款识别、混合召回和业务重排，取得如下提升：

| 指标 | 基线版本 | 优化版本 |
|---|---:|---:|
| Recall@5 | 52.00% | 84.00% |
| MRR | 45.96% | 77.01% |
| Top-1 条款准确率 | 40.00% | 72.00% |
| nDCG@5 | 44.16% | 76.76% |

指标文件位于 `data/eval`。以上指标用于衡量检索质量，不等同于最终业务审批意见。

## 技术架构

```text
法规资料
  -> 文档解析与元数据治理
  -> 条款级 / 表格级 / 图示说明分块
  -> SQLite 文档库 + FTS5 全文索引 + Embedding 向量
  -> 向量检索 + BM25 检索 + 关键词规则召回
  -> RRF 融合
  -> 条款号 / 地区 / 效力状态 / 内容类型业务重排
  -> LLM 摘要生成
  -> 引用来源 + 原文片段 + 风险提示
```

当前 Demo 使用 FastAPI + SQLite + FTS5 构建轻量化服务，便于本地运行和面试展示。Embedding 与生成模型采用可配置方式，支持本地 Hash 向量用于离线演示，也支持 OpenAI 兼容接口接入中文 Embedding 和大语言模型。

## 检索流程

1. 用户输入自然语言问题。
2. 系统进行 Query 预处理，包括长度控制、噪声清洗、实体识别和法规关键词识别。
3. Query 理解层抽取业务对象、地区、条款号、设施类型等信息。
4. 检索层并行执行向量召回、BM25 召回和关键词召回。
5. 使用 RRF 对多路结果融合，减少单一路径漏召回风险。
6. 重排层根据法规效力、地区层级、条款号匹配、内容类型和得分进行二次排序。
7. 生成层基于 Top-K 证据组织回答，并强制附带引用来源。
8. 前端展示答案、证据卡片、原文入口和免责声明。

## 本地运行

```powershell
cd city-planning-rag
python -m pip install -r requirements.txt
python -m app.cli ingest
python -m uvicorn app.api:app --host 127.0.0.1 --port 8000
```

打开 `http://127.0.0.1:8000` 查看演示界面。

常用命令：

```powershell
python -m app.cli search "养老服务设施如何配置"
python -m app.cli ask "申请建设工程规划许可证需要哪些材料"
python -m app.cli eval --dataset data/eval/formal_retrieval_v1.jsonl --top-k 10
python -m unittest discover -s tests -v
```

可选模型与环境变量配置见 `.env.example`。请勿将真实 API Key 提交到仓库。

## API

- `GET /health`：查看文档数量、分块数量和当前向量配置。
- `POST /ingest`：执行增量入库。
- `POST /search`：返回法规检索结果。
- `POST /ask`：返回带引用来源的问答结果。

## 数据治理

每份文档入库时会保留以下信息：

- 基础信息：标题、文号、发布机关、发布日期、适用地区。
- 效力信息：现行有效、试行、废止、失效或历史版本。
- 来源信息：原始文件路径、官方来源链接、页码或章节位置。
- 结构信息：章节、条款号、内容类型、表格/图示标记。
- 更新信息：内容哈希、入库时间、最近更新时间。

这套元数据用于检索过滤、结果排序、冲突提示和后续版本淘汰。

## 评测方法

测试集按业务场景分层构建，包括：

- 条款精确定位题：验证法规名称、章节和条款号是否命中。
- 业务条件题：验证系统能否召回包含适用条件的条文。
- 多法规对照题：验证上位规范与地方规范的组合检索能力。
- 易混淆问题：验证同类设施、相近名词和旧版规范的区分能力。

迭代时固定测试集，只调整分块、召回、融合和重排策略，避免为了指标临时改题。

## 适用边界

本项目输出用于辅助法规检索和资料核验，不替代自然资源、规划审批或行业主管部门的正式解释与审批意见。涉及最终决策时，应以官方文件原文和主管部门意见为准。
