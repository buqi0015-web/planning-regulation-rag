# 从 0 到 1 搭建城市规划法规 RAG

## 先理解目标

这个项目不是做一个“懂规划的聊天机器人”，而是做一个能够：

- 从可信来源管理法规；
- 找到适用地区、现行版本和相关条款；
- 基于条文回答并展示依据；
- 在证据不足或冲突时停止猜测；
- 用评测数据持续优化；

的法规检索与辅助问答系统。

最重要的产品指标不是回答听起来是否专业，而是：

1. 正确条款有没有进入 Top 5；
2. 回答引用是否真的支持结论；
3. 是否误用了废止、旧版或异地法规。

## 阶段一：定义范围

不要一开始收集全国全部法规。先选择一个地区和一个高频主题，例如：

- 建筑退让；
- 建筑高度与容积率；
- 历史文化保护；
- 建设工程规划许可；
- 公共服务设施配置。

MVP 建议控制在 20 至 50 份正式文件、100 个真实问题。先证明系统能稳定找对，再扩大范围。

产出物：

- 用户清单：规划从业者、设计单位、审批辅助人员等；
- 问题清单：用户实际会怎样提问；
- 法规清单：每份文件的官方来源和效力状态；
- 禁止边界：系统不替代正式审批与法律意见。

## 阶段二：建立法规数据规范

每份文档至少保存以下元数据：

| 字段 | 用途 |
|---|---|
| `title` | 展示法规名称与精确检索 |
| `document_no` | 区分同名文件 |
| `authority` | 判断来源权威性 |
| `jurisdiction` | 防止跨地区误用 |
| `effective_date` | 判断时效 |
| `status` | 过滤草稿、废止和归档文件 |
| `version` | 发现多版本冲突 |
| `source_url` | 让用户回到官方原文核验 |

真实项目应建立人工复核流程。网页抓取成功不等于法规数据正确，文件效力状态尤其需要核验。

## 阶段三：文档处理与分块

普通文章可以按 500 字切分，但法规优先按条文切分，因为一条通常表达一个相对完整的规则。

本项目的 `split_regulation()` 顺序是：

1. 检测“第一条、第二条”等条款；
2. 没有条款时按 Markdown 标题；
3. 仍无法识别时才按固定长度兜底。

检查分块质量时，随机抽取 30 个 chunk，确认：

- 条款没有从中间断开；
- 上下文包含法规名称与条款号；
- 表格、附件和例外条件没有丢失；
- 每个 chunk 都能追溯到原文件。

## 阶段四：先做检索，不急着接大模型

RAG 的核心是先找到正确证据。建议依次完成：

1. 精确检索：法规名称、文号、条款号；
2. 关键词检索：例如“主干路、退让、高层建筑”；
3. 语义检索：例如“楼要离主路多远”；
4. 混合检索：融合精确匹配与语义匹配；
5. 重排序：对候选条款进行二次精排。

本项目为了零成本启动，使用 SQLite FTS5 与本地哈希向量，再通过 RRF 融合。后续可将 `hashed_vector()` 替换为中文 Embedding 服务。

## 阶段五：建立评测集

不要凭感觉调参数。建立 JSONL 评测集，每条至少包括：

```json
{
  "query": "高层建筑沿主干路一般需要退让多少米？",
  "expected_title": "对应法规名称",
  "expected_section": "第四条"
}
```

评测集建议包含：

- 50% 真实高频问题；
- 20% 口语、简称和错别字问题；
- 15% 多条件与跨条款问题；
- 10% 旧版本、异地法规等冲突问题；
- 5% 知识库无答案问题。

先优化 `Recall@5`，再优化 `MRR`。正确条款没有被召回时，生成模型再强也无法可靠回答。

## 阶段六：生成与引用

接入大模型时，Prompt 必须要求：

- 只能使用提供的证据；
- 每个关键结论标注引用；
- 证据不足时明确说不知道；
- 多版本冲突时展示差异；
- 不输出正式审批结论；
- 引导用户打开官方原文核验。

还要单独评测“引用正确率”：引用存在不代表引用真的支持回答。

## 阶段七：生产化补强

上线前至少补齐：

- PDF、扫描件和表格解析；
- 法规增量同步与效力状态复核；
- 地区、项目类型和用户权限过滤；
- 中文 Embedding 与 Reranker；
- 查询改写、同义词和专业术语词典；
- 全链路日志、监控、反馈入口；
- Bad Case 分级、修复和回归评测。

## 每周练习任务

第一周：加入 10 份核验过的正式文件，完成 30 个问题的评测集。

第二周：分析所有未命中问题，分别判断是数据、分块、检索还是元数据过滤问题。

第三周：接入 Embedding 和 Reranker，对比优化前后的 Recall@5、MRR 与响应时间。

第四周：接入生成模型，新增引用正确率、无依据回答率和冲突提示率评测。

完成后，你得到的不只是一个 Demo，而是一套可以在面试或真实项目中清楚解释的数据治理、检索、生成、评测和运营闭环。
