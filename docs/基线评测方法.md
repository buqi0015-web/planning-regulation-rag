# RAG 基线评测方法

## 1. 为什么先做基线

使用同一份冻结评测集，分别评估 Hash、真实 Embedding、加入 Reranker 后的系统。
每次只改变一个变量，否则无法判断指标提升来自哪项改动。

## 2. 检索指标

- `Recall@K`：正确证据是否出现在前 K 条结果中。RAG 首要指标，推荐重点看 `Recall@5`。
- `MRR`：第一条正确证据排名的倒数均值，越接近 1 越好。
- `Top-1 Section Accuracy`：第一条结果是否就是标注条款，适合衡量直接问答体验。
- `Title Hit@K`：前 K 条是否命中正确规范，区分“找对文档”和“找对条款”。
- `nDCG@K`：考虑多个相关证据时的排序质量。
- `Precision@K`：前 K 条中相关证据比例。单条正确证据任务中通常低于 Recall，不应单独使用。

建议门槛：

| 指标 | Demo目标 | 生产候选目标 |
| --- | ---: | ---: |
| Recall@5 | >= 0.85 | >= 0.95 |
| MRR | >= 0.70 | >= 0.85 |
| Top-1 Section Accuracy | >= 0.65 | >= 0.80 |

## 3. 回答质量指标

检索正确不代表回答正确。回答评测至少检查：

- `Faithfulness`：结论是否都能由引用证据支持。
- `Citation Correctness`：引用是否指向支持该结论的规范和条款。
- `Answer Relevance`：是否直接回答问题，没有无关扩写。
- `Completeness`：问题要求的要点是否遗漏。
- `Abstention Accuracy`：证据不足时是否拒绝编造。

正式评测建议由两名人工复核者使用 0-2 分量表；LLM Judge 仅用于扩大样本，不能替代人工抽检。

## 4. 评测集设计

至少准备 100 道真实问题，并按类型分层：

- 40 道正文条款问答
- 20 道数值、阈值和单位问题
- 15 道表格查询
- 10 道图示查询
- 10 道跨规范综合问题
- 5 道无答案/应拒答问题

每题必须人工标注正确规范、条款、内容类型和可接受答案要点。评测集不得参与提示词调试。

## 5. 当前命令

```powershell
# 保存当前系统基线
python -m app.cli eval --dataset data/eval/questions.jsonl --top-k 5 --output data/eval/reports/baseline.json

# 修改模型或检索策略后再次评测
python -m app.cli eval --dataset data/eval/questions.jsonl --top-k 5 --output data/eval/reports/candidate.json
```

对比时重点查看总体指标、`by_category` 和 `failures`。失败题应回溯到解析、切块、召回、排序或回答生成中的具体环节。
